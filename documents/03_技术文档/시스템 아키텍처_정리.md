# 부록. 시스템 아키텍처

## 1. 개요

본 연구에서 개발한 자기공감 대화 애플리케이션은 사용자, 프런트엔드, 백엔드, 인공지능, 데이터 관리의 다섯 요소로 구성된다. 사용자는 웹 기반 프런트엔드를 통해서만 시스템과 상호작용하며, 프런트엔드는 백엔드와 HTTP API로 통신한다. 인공지능 모델과 데이터베이스는 백엔드를 매개로 해서만 접근되며, 프런트엔드가 이들에 직접 접근하는 경로는 존재하지 않는다.

이러한 계층 구조는 두 가지 목적을 가진다. 첫째, 위기 상황 감지, 대화 흐름 결정, 데이터 보관 여부 판단 등 안전 및 개인정보와 관련된 결정을 백엔드의 규칙 기반 코드에서 일관되게 수행함으로써, 생성형 AI의 출력에 의존하지 않도록 한다. 둘째, 사용자 데이터에 대한 접근을 단일 경로로 제한하여 인증과 권한 검사를 일관되게 적용할 수 있도록 한다.

## 2. 구성 요소별 역할과 구현

### 2.1 프런트엔드

프런트엔드는 사용자가 직접 이용하는 단일 페이지 웹 애플리케이션으로, 언어 선택, 대화 시작, 성찰일지 작성, 저장 기록 조회 기능을 제공한다. 인터페이스는 중국어, 한국어, 영어를 지원하며 사용자는 모든 화면에서 언제든 언어를 전환할 수 있다. 대화는 중국어 또는 한국어로 진행되며, 중국어나 한국어로 전환하면 진행 중인 대화의 이후 응답도 해당 언어로 생성된다. 영어는 인터페이스 언어로만 제공된다.

**[표 A-1] 프런트엔드 구현 기술**

| 구분 | 기술 | 용도 |
|---|---|---|
| 프레임워크 | Vue 3 (Composition API), TypeScript | 화면 및 컴포넌트 구성, 타입 검사 |
| 빌드 | Vite | 개발 환경 및 배포용 번들 생성 |
| 라우팅 | Vue Router | 화면 전환, 화면별 지연 로딩, 로그인 확인 |
| 상태 관리 | Pinia | 로그인 상태, 진행 중인 대화 상태 |
| 다국어 | vue-i18n | 중국어 · 한국어 · 영어 인터페이스 |
| 네트워크 | axios | 백엔드 API 호출 |
| 코드 검사 | vue-tsc, ESLint, oxlint | 타입 및 코드 규칙 검사 |
| 배포 | Cloudflare Workers | 정적 자산 배포 |

**[표 A-2] 화면 구성**

| 경로 | 화면 | 로그인 필요 |
|---|---|---|
| `/` | 대화 (시작 전 사전 안내 포함) | 예 |
| `/history` | 대화 기록 | 예 |
| `/records` | 내 기록 (모든 대화에서 저장한 기록, 유형별 필터) | 예 |
| `/reflection` | 매일 사용 성찰일지 | 예 |
| `/help` | 도움말 및 지원 기관 안내 | 아니요 |
| `/privacy` | 개인정보 처리 안내 | 아니요 |
| `/contact` | 문의하기 | 아니요 |
| `/login`, `/register` | 로그인, 회원가입 (아이디 · 비밀번호) | 아니요 |

로그인이 필요한 화면에 로그인하지 않은 상태로 접근하면 로그인 화면으로 이동하며, 로그인 후 원래 화면으로 돌아간다.

**[구조 A-1] 프런트엔드 디렉터리 구조**

```
frontend/src/
├── api/client.ts        백엔드 API 호출 및 데이터 타입
├── views/               화면: 대화, 대화 기록, 내 기록, 성찰일지, 도움말,
│                        개인정보 처리 안내, 문의하기, 로그인 · 회원가입, 관리자
├── components/          공통 컴포넌트: 사이드바, 상단 메뉴, 언어 전환,
│   │                    사전 안내 대화상자, 선택 카드 등
│   └── admin/           관리자 기능: AI 대화 설정 편집, 모델 선택, 성찰일지 조회
├── content/             개인정보 처리 안내, 연락처 (중 · 한 · 영)
├── stores/              전역 상태 (로그인, 진행 중인 대화)
├── i18n/                인터페이스 문구 (중 · 한 · 영) 및 언어 설정
├── router/              화면 경로 및 로그인 확인
└── utils/               기록 항목명 변환, 로그인 후 이동, 대화 내보내기
```

### 2.2 백엔드

백엔드는 프런트엔드의 요청을 처리하고 인공지능 및 데이터베이스와의 연동을 담당한다. 주요 기능은 사용자 및 세션 관리, 대화 목적 · 상태 및 활동 경로 관리, 맥락 조회 및 프롬프트 구성, AI API 연동 및 응답 처리, 활동 · 기록 · 사용 로그 관리이다.

프롬프트는 공통 원칙, 대화 목적별 흐름 지침, 고정된 응답 형식 요구사항의 세 부분으로 조합된다. 이 중 공통 원칙과 흐름 지침은 연구진이 관리자 페이지에서 코드 수정 없이 조정할 수 있으며, 모든 수정 내용은 버전으로 보관되고 각 AI 응답에는 생성 당시의 프롬프트 버전과 모델명이 함께 기록된다.

**[표 A-3] 백엔드 구현 기술**

| 구분 | 기술 | 용도 |
|---|---|---|
| 언어 · 프레임워크 | Python 3.12, FastAPI, Uvicorn | API 서버 및 비동기 요청 처리 |
| 데이터 접근 | SQLAlchemy 2 (비동기), aiosqlite | 데이터베이스 연동 |
| 데이터 검증 | Pydantic, pydantic-settings | 입출력 형식 검증, 환경 설정 |
| 인증 | JWT (PyJWT), PBKDF2 비밀번호 해시 | 아이디 · 비밀번호 기반 로그인 |
| 암호화 | Fernet (cryptography) | 저장 기록 및 성찰일지 암호화 |
| 문서 생성 | python-docx, ReportLab | 관리자용 Word · PDF 내보내기 |
| 의존성 관리 | uv | 패키지 버전 고정 |
| 배포 | Docker | 서버 환경 구성 |

**[구조 A-2] 백엔드 디렉터리 구조**

```
backend/app/
├── main.py              애플리케이션 진입점, API 등록
├── api/                 API 계층 (기능별 파일, [표 A-4] 참조)
├── services/            처리 로직

│   │                       네 가지 대화 흐름 지침
```

### 2.3 인공지능

인공지능은 OpenAI API를 통해 연동되며, 응답은 사전에 정의된 JSON 형식(응답 문장과 선택지)으로 반환된다. 기본 모델은 gpt-5.6-terra이며, 관리자는 최근 출시된 모델 가운데 실제 호출이 확인된 모델로 변경할 수 있다.

인공지능이 담당하는 역할은 상황 · 맥락의 이해 및 요약, 감정 및 필요 탐색 질문 생성, 자기수용 표현 제안, 조절 활동 제안, 사용자의 수정 · 거부 내용 반영이다. 인공지능이 제시하는 감정, 해석, 표현은 모두 후보로 제시되며, 사용자가 확인한 내용만 대화 맥락으로 저장된다.

### 2.4 데이터 관리

데이터는 관계형 데이터베이스(SQLite)에 저장된다. 저장 대상은 사용자 동의 정보, 대화 기록, 성찰일지, 사용 일시 및 횟수 기록이다. 사용자가 저장을 선택한 기록과 성찰일지는 암호화되어 보관되며, 대화 기록은 사용자의 보관 동의 여부에 따라 대화 종료 시 삭제된다.

**[표 A-5] 주요 데이터 테이블**

| 테이블 | 내용 |
|---|---|
| `users` | 아이디, 비밀번호 해시, 역할(일반 사용자 · 관리자 · 최고 관리자), 사용 여부 |
| `sessions` | 대화 단위: 소속 사용자, 대화 언어, 동의 항목, 사용자가 확인한 맥락, 시작 · 종료 시각 |
| `messages` | 대화 메시지; AI 응답에는 생성 당시의 프롬프트 버전과 모델명 기록 |
| `saved_records` | 사용자가 저장한 기록 (암호화) |
| `daily_reflections` | 매일 사용 성찰일지 (사용자당 하루 1건, 암호화) |
| `prompt_versions` | 관리자가 수정한 프롬프트의 전체 버전 이력 |
| `app_settings` | 관리자가 선택한 사용 모델 등 운영 설정 |
| `crisis_resources` | 검증된 지원 기관 정보 (중 · 한 · 영) |

### 2.5 관리자 기능과 권한

관리자 페이지는 연구진이 데이터를 검토하고 시스템을 운영하기 위한 기능을 제공한다. 권한은 관리자와 최고 관리자의 두 단계로 구분되며, 최고 관리자 계정은 관리자 페이지에서 생성하거나 변경할 수 없다.

**[표 A-6] 관리자 기능과 권한**

| 기능 | 관리자 | 최고 관리자 |
|---|---|---|
| 대화 데이터 조회 (참여자 아이디 표시) 및 필터 | ○ | ○ |
| 대화 데이터 내보내기 (JSON · PDF · Word · Markdown · TXT) | ○ | ○ |
| 성찰일지 조회 및 내보내기 (CSV · JSON) | ○ | ○ |
| 계정 생성, 비밀번호 재설정, 사용 중지 · 복구, 삭제 | 일반 사용자 | 일반 사용자 · 관리자 |
| 관리자 지정 · 해제 | × | ○ |
| 프롬프트(AI 대화 설정) 수정 | ○ | ○ |
| 사용 모델 변경 | ○ | ○ |

## 3. 대화 처리 절차

한 차례의 대화는 다음 절차에 따라 처리된다.

1. 사용자가 프런트엔드에서 메시지를 입력하면 백엔드로 전달된다.
2. 백엔드는 먼저 규칙 기반의 위기 키워드 검사를 수행한다. 위기 신호가 감지되면 인공지능을 호출하지 않고 사전에 검증된 지원 기관 정보를 즉시 제공한다.
3. 위기 신호가 없는 경우, 사용자가 선택한 대화 목적과 자기비판 수준에 따라 대화 흐름을 결정한다.
4. 데이터베이스에서 최근 대화 내용과 사용자가 확인한 맥락을 조회하여 프롬프트를 구성하고, 인공지능에 응답을 요청한다.
5. 인공지능이 생성한 응답과 선택지를 저장한 후 프런트엔드에 전달하며, 프런트엔드는 이를 대화 말풍선과 선택 카드로 표시한다.
6. 사용자가 요약, 계획, 자기친절 표현 등을 확인한 후 저장을 선택하면, 해당 기록은 보관 동의와 함께 암호화되어 저장된다.

| 계정 기반 접근 통제 | 모든 이용은 로그인을 전제로 하며, 사용자는 본인의 데이터에만 접근할 수 있다. |

## 5. 핵심 구현 코드

본 절은 앞서 기술한 설계 원칙이 실제로 구현된 부분을 소스 코드에서 발췌한 것이다. 각 코드는 실제 시스템의 코드를 그대로 옮겼으며, 백엔드 코드의 경로는 `backend/` 기준이며(디렉터리 구조는 [구조 A-2] 참조), 프런트엔드 코드는 `frontend/src/` 기준이다.

### 5.1 위기 신호 감지

위기 신호는 인공지능의 판단에 의존하지 않고, 중국어와 한국어의 위기 표현 목록을 정규식으로 대조하여 판정한다. 결과는 위기(CRISIS), 주의(WATCH), 해당 없음(NONE)의 세 단계로 구분된다.

**[코드 A-1] 위기 표현 목록 및 판정 함수** (`app/services/safety.py`)

```python
_CRISIS_PATTERNS_ZH = [
    r"不想活", r"自杀", r"想死", r"结束生命", r"伤害自己", r"割腕", r"想杀", r"杀了他", r"杀了她",
]
_CRISIS_PATTERNS_KO = [
    r"죽고\s*싶", r"자살", r"자해", r"삶을\s*끝", r"죽이고\s*싶", r"살고\s*싶지\s*않",
]


def screen_text(text: str) -> RiskLevel:
    if _matches(text, _CRISIS_PATTERNS_ZH) or _matches(text, _CRISIS_PATTERNS_KO):
        return RiskLevel.CRISIS
    if _matches(text, _WATCH_PATTERNS_ZH) or _matches(text, _WATCH_PATTERNS_KO):
        return RiskLevel.WATCH
    return RiskLevel.NONE
```

이 검사는 매 대화 턴에서 인공지능을 호출하기 전에 수행되며, 위기로 판정되면 인공지능을 거치지 않고 검증된 지원 기관 정보를 반환한다.

**[코드 A-2] 대화 처리 시 위기 검사 순서** (`app/services/dialogue_state.py`)

```python
risk = RiskLevel.NONE
if user_text:
    risk = safety.screen_text(user_text)
    session.self_criticism_level = safety.bump_self_criticism(user_text, session.self_criticism_level)
    if risk == RiskLevel.CRISIS:
        return await _crisis_turn(db, language)
```

위기로 판정된 경우 반환되는 응답은 고정 문구와 데이터베이스에 등록된 지원 기관 정보로만 구성되며, 각 기관 정보에는 연구진이 연락처를 확인한 일시(`verified_at`)가 함께 포함된다.

```python
    resources = result.scalars().all()
```

### 5.3 프롬프트 구성

시스템 프롬프트는 공통 원칙(13개 항목), 대화 흐름별 지침, 응답 형식 요구사항, 응답 언어 지정의 순서로 조합된다. 공통 원칙과 흐름 지침은 관리자 페이지에서 수정할 수 있으나, 응답 형식과 응답 언어 지정은 코드에 고정되어 있어 수정되지 않는다.

**[코드 A-5] 공통 원칙 조합 및 시스템 프롬프트 구성** (`app/prompts/principles.py`, `app/prompts/base.py`)

```python
def build_rules_text(bodies: dict[str, str], language: Language) -> str:
    parts = [f"【{TITLES[key][language]}】\n{bodies[key].strip()}" for key in KEYS if bodies.get(key, "").strip()]
    return "\n\n".join(parts)


def build_system_prompt(rules_text: str, flow_instructions: str, language: Language, flow_format: str) -> str:
    return (
        f"{rules_text}\n\n---\n{flow_instructions}\n\n---\n{FORMAT_RULES[language]}\n{flow_format}"
        f"\n{REPLY_LANGUAGE[language]}"
    )
```

인공지능에는 다음의 응답 형식이 함께 전달되며, 응답은 사용자에게 보여 줄 문장(`reply_text`)과 선택지(`candidates`)로 구성된 JSON으로 받는다.

**[코드 A-6] 응답 형식 지정** (`app/services/llm.py`)

```python
RESPONSE_INSTRUCTIONS = (
    "\n\n---\n"
    "输出格式 / Output format: 只返回一个 JSON 对象 / return exactly one JSON object, "
    '{"reply_text": string, "candidates": [{"type": string, "items": [{"id": string, "label": string}]?, '
    '"fields": object?}]}. reply_text 是给用户看的简短消息；candidates 是可选的结构化建议，'
    "没有则给空数组。不要在 JSON 之外输出任何文字。"
```

구성된 프롬프트와 최근 대화 내역은 관리자가 선택한 모델로 전송된다. 응답이 JSON 형식이 아닌 경우에도 대화가 중단되지 않도록 응답 전체를 문장으로 처리하며, API 호출이 실패하면 오류 원인을 기록한 뒤 사용자에게 일시적 오류임을 알린다.

**[코드 A-7] 인공지능 호출 및 응답 해석** (`app/services/llm.py`)

```python
async def generate_turn(
    system_prompt: str,
    history: list[dict[str, str]],
    user_message: str,
    model: str,
) -> LLMResponse:
    messages = [{"role": "system", "content": system_prompt + RESPONSE_INSTRUCTIONS}]
    messages.extend(history)
    messages.append({"role": "user", "content": user_message})

    try:
        completion = await _client().chat.completions.create(
            model=model,
            messages=messages,
            response_format={"type": "json_object"},
        )
    except APIError as e:
        logger.exception("OpenAI call failed (model=%s)", model)
        status = getattr(e, "status_code", None)
        raise LLMUnavailable(f"{type(e).__name__}{f' {status}' if status else ''}") from e
    raw = completion.choices[0].message.content or "{}"
    try:
        parsed = json.loads(raw)
    except json.JSONDecodeError:
        parsed = {"reply_text": raw, "candidates": []}

    return LLMResponse(
        reply_text=parsed.get("reply_text", ""),
        candidates=parsed.get("candidates", []) or [],
    )
```

```python
    ctx = dict(session.confirmed_context or {})
    card_type = confirmation.get("card_type")
    selected = confirmation.get("selected_labels", [])
    custom = confirmation.get("custom_text")
```

```python
    return _fernet().encrypt(json.dumps(payload, ensure_ascii=False).encode("utf-8"))


def decrypt_json(token: bytes | str) -> dict:
    if isinstance(token, str):
        token = token.encode("utf-8")
    return json.loads(_fernet().decrypt(token).decode("utf-8"))
```
