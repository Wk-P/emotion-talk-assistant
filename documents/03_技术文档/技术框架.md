# 技术框架总结

本项目是一个前后端分离的网页应用：前端负责界面和交互，后端负责对话逻辑、安全筛查、数据存储和调用 AI 模型。两者通过 HTTP 接口通信。

```
用户浏览器 ──► 前端（Vue 单页应用，部署在 Cloudflare）
                 │  HTTP 接口（/api/...）
                 ▼
             后端（FastAPI，Docker 部署）
                 ├─► SQLite 数据库（对话、用户、记录、提示词版本）
                 └─► OpenAI 模型（生成回复）
```

## 一、前端

| 类别 | 选型 | 用途 |
|---|---|---|
| 框架 | Vue 3（组合式写法 `<script setup>`） | 页面与组件 |
| 语言 | TypeScript | 类型检查，减少低级错误 |
| 构建 | Vite | 本地开发与打包 |
| 路由 | Vue Router | 页面切换；页面按需加载 |
| 状态管理 | Pinia | 登录状态（`stores/auth.ts`）、当前对话（`stores/session.ts`） |
| 多语言 | vue-i18n | 中文 / 韩文两套文案，集中在 `src/i18n/index.ts` |
| 网络请求 | axios | 统一封装在 `src/api/client.ts` |
| 代码检查 | vue-tsc、ESLint、oxlint | 类型检查与代码规范 |
| 部署 | Cloudflare Workers（静态资源） | `npm run deploy`，配置见 `wrangler.jsonc` |

### 目录结构

```
frontend/src/
├── api/client.ts        所有后端接口的调用与数据类型
├── views/               页面：聊天、历史、记录、帮助、登录注册、管理后台
├── components/          通用组件：菜单、侧边栏、知情同意弹窗、选项卡片等
│   └── admin/           管理后台的「AI 对话设置」编辑器
├── stores/              全局状态（登录、当前对话）
├── i18n/                中韩文案与语言偏好
├── router/              路由与管理页权限守卫
└── assets/main.css      全局样式变量（颜色、圆角、阴影）
```

### 页面一览

| 路径 | 页面 | 是否需要登录 |
|---|---|---|
| `/` | 聊天（含开场知情说明） | 是 |
| `/history` | 历史对话 | 是 |
| `/records` | 我的记录（该用户所有对话中保存的记录，可按类型筛选） | 是 |
| `/reflection` | 每日使用感受记录 | 是 |
| `/help` | 帮助与联系（关于本工具、求助资源、常见问题、联系我们；`/contact` 自动跳转到这里） | 否 |
| `/privacy` | 用户隐私协议 | 否 |
| `/login` `/register` | 登录、注册（账号 ID + 密码） | 否 |

> 没有匿名使用：未登录时访问需要登录的页面，会先跳到登录页，登录后自动回到原页面。后端接口同样要求登录，并且用户只能访问自己的对话、记录和每日使用感受记录。

## 二、后端

| 类别 | 选型 | 用途 |
|---|---|---|
| 语言 | Python 3.12 | |
| 框架 | FastAPI + Uvicorn | 提供接口，异步处理请求 |
| 数据校验 | Pydantic / pydantic-settings | 请求与返回的数据格式、读取 `.env` 配置 |
| 数据库 | SQLite（aiosqlite）+ SQLAlchemy 2（异步） | 数据文件在 `backend/data/app.db` |
| AI 模型 | OpenAI 接口 | 生成每轮回复和候选选项。模型可在后台切换，未选择时使用 `.env` 的 `OPENAI_MODEL` |
| 登录认证 | 账号 ID + 密码；JWT（PyJWT）+ 密码哈希 | 不使用邮箱。登录有效期 30 天，停用账号立即失效 |
| 数据加密 | cryptography（Fernet） | 用户保存的记录在数据库中加密存储 |
| 依赖管理 | uv | `pyproject.toml` + `uv.lock` |
| 部署 | Docker（`Dockerfile`、`docker-compose.yml`） | 数据目录挂载为卷，重启不丢数据 |

### 目录结构

```
backend/app/
├── main.py              应用入口，注册所有接口
├── api/                 接口层（按功能分文件）
├── services/            业务逻辑
│   ├── dialogue_state.py   对话主流程：安全筛查 → 选择流程 → 调用模型 → 整理结果
│   ├── safety.py           危机关键词筛查（代码判断，不依赖 AI）
│   ├── llm.py              调用 OpenAI，并固定要求模型按 JSON 格式返回
│   ├── auth.py             密码哈希、登录凭证、ID 规则
│   └── crypto.py           记录加密
├── prompts/             AI 提示词
│   ├── principles.py       共同原则：按指导意见2分成 13 项（可在后台逐项修改）
│   ├── base.py             拼装完整说明 + 固定格式要求
│   ├── intent_question.py  确认需要的问题（可在后台修改）
│   ├── emotion_exploration.py / stabilization.py / recovery_plan.py / self_kindness.py
│   │                       四个对话流程的说明（可在后台修改）与各自的固定格式要求
│   ├── router.py           根据用户选择和自我批评程度决定用哪个流程
│   └── registry.py         后台可编辑项的默认值与版本读取
├── models/              数据表定义
├── schemas/             接口的请求 / 返回格式
├── db/                  数据库连接与启动时的初始化
└── core/config.py       配置项（读取 .env）
```

### 接口分组

| 前缀 | 文件 | 内容 |
|---|---|---|
| `/api/session` | `session.py` | 开始对话、开场问题、历史列表、切换语言、删除单个对话（只能删自己的） |
| `/api/chat` | `chat.py` | 发送消息，返回 AI 回复与候选卡片 |
| `/api/session/{id}/consent`、`/end` | `consent.py` | 知情同意的各项选择、结束对话（未同意保存则清除消息） |
| `/api/records` | `records.py` | 保存记录、列出本人全部记录、删除（只能删自己的） |
| `/api/resources` | `resources.py` | 危机求助资源（来自固定数据，不由 AI 生成） |
| `/api/auth` | `auth.py` | 注册（注册后直接登录）、登录、获取当前用户 |
| `/api/admin` | `admin.py` | 管理后台：对话数据（筛选、导出）、用户管理（新建账号、重设密码、筛选、停用 / 恢复、角色、删除） |
| `/api/admin/prompts` | `prompts.py` | AI 对话设置：查看、保存新版本、版本记录、试聊 |
| `/api/admin/model` | `ai_model.py` | AI 模型：列出最近 3 个月可用的聊天模型，管理员可切换 |

### 主要数据表

| 表 | 内容 |
|---|---|
| `users` | 账号 ID、密码哈希、角色（普通用户 / 管理员 / 超级管理员）、是否启用 |
| `sessions` | 每次对话：所属用户、语言、知情同意选项、已确认的情绪与情境 |
| `messages` | 对话消息；AI 回复会记下当时使用的提示词版本 |
| `saved_records` | 用户保存的记录（加密） |
| `prompt_versions` | 后台修改的提示词，每次保存一个新版本，可回滚 |

> 目前没有使用数据库迁移工具：启动时自动建表，新增字段在 `db/session.py` 里手动补上。
>
> 账号 ID 存在 `users` 表原来名为 `email` 的列里，所以以前用邮箱注册的用户可以继续用邮箱作为 ID 登录。旧的 `auth_tokens` 表已不再使用，可以留着不管。

## 三、一轮对话是怎么完成的

1. 前端把用户输入发送到 `/api/chat`。
2. 后端先用 `safety.py` 做**关键词筛查**：一旦发现危机信号，直接返回固定的求助信息，不经过 AI。
3. `prompts/router.py` 根据用户开场的选择（倾诉 / 整理情绪 / 稳定状态 / 寻找方法）和自我批评程度，**选出对话流程**。
4. 拼出发给 AI 的完整说明：13 项共同原则 + 流程说明（这两部分可在后台修改）+ 固定格式要求（写死在代码里）。
5. `llm.py` 调用模型，要求按固定 JSON 格式返回「回复文字 + 候选选项」。
6. 把结果交给前端，显示成聊天气泡和选项卡片。（目前只筛查用户说的话，AI 的回复不再额外筛查。）
7. 用户点选的内容才会写入「已确认信息」，AI 的猜测不会直接写入。
8. 确认小结、计划、对自己友善的话或恢复行动后，用户可以点「保存到我的记录」。点保存即表示同意保存这一条，记录加密后存入数据库。

## 四、管理后台与权限

| 功能 | 管理员 | 超级管理员 |
|---|---|---|
| 查看对话数据（匿名编号，不显示账号 ID） | ✓ | ✓ |
| 按参与者、语言、日期、消息数筛选对话 | ✓ | ✓ |
| 导出全部 / 筛选结果 / 单个参与者的对话（含用户保存的记录） | ✓ | ✓ |
| 查看每次对话中用户保存的记录 | ✓ | ✓ |
| 用户列表 | 只看到普通用户 | 看到普通用户和管理员 |
| 按 ID、状态筛选用户；导出某个用户的对话 | ✓ | ✓（还可按角色筛选） |
| 新建账号 | 仅普通用户 | 普通用户和管理员 |
| 重设密码、停用 / 恢复、删除用户 | 仅普通用户 | 普通用户和管理员 |
| 设为 / 取消管理员 | ✗ | ✓ |
| 修改 AI 对话设置 | ✓ | ✓ |

- 任何人都不能通过后台操作超级管理员账号；设为超级管理员只能直接改数据库。
- 用户可以自己注册（账号 ID + 密码，注册后直接可用），也可以由管理员代为新建。
- 系统没有邮箱，所以没有「忘记密码」功能：用户忘记密码时联系管理员，由管理员重设后告知用户。
- 导出文件为 JSON 格式，参与者以匿名编号（如 `P-1a2b3c4d`）出现，不含账号 ID。

## 五、本地运行

```bash
# 后端
cd backend
cp .env.example .env        # 填入 OPENAI_API_KEY、JWT_SECRET、RECORD_ENCRYPTION_KEY 等
uv sync
uv run uvicorn app.main:app --reload --port 8000

# 前端
cd frontend
cp .env.example .env        # 指向后端地址
npm install
npm run dev                 # 默认 http://localhost:5173
```
