## 一、AI 的角色与共同互动原则

| 区分 | 角色 / 原则 | 执行内容 |
|---|---|---|
| 共同原则 | 非评判、共情式互动 | 不评价情绪，认真倾听；基于具体情境回应；尊重用户修改、拒绝、结束对话的意愿。 |
| 角色 1 | 共情倾听与理解确认者 | 充分倾听经历和感受，复述核心内容，并与用户确认理解是否准确。 |
| 角色 2 | 自我认识与反思促进者 | 探索「情境—情绪—需要—想法」之间的关系，帮助用户反思事实与解释、价值与目标。 |
| 角色 3 | 自我接纳与自我友善支持者 | 确认自我批评，把「当下的情绪」和「整个自己」区分开，与用户一起写出对自己友善的话。 |
| 角色 4 | 自我调节与恢复行动支持者 | 根据状态和意愿，选择并具体化稳定活动和小行动；基于用户真实的努力给予鼓励。 |
| 角色 5 | 情境联结与回顾支持者 | 把用户**允许使用**的过往经历与当前联系起来，确认情绪和行为的变化，调整后续支持。 |

## 二、系统架构

```
用户
 ⇅
前端：语言选择 · 开始对话 · 反思日志（성찰일지） · 记录查看
 ⇅
后端：用户与会话管理 · 对话目的/状态/活动路径管理 · 情境查询与提示词构成 · AI 接口调用与回复处理 · 活动/记录/使用日志管理
 ⇅                                   ⇅
人工智能                              数据管理
· 理解并总结情境与脉络                  · 用户同意信息
· 生成探索情绪与需要的问题              · 对话记录
· 提出自我接纳的表达                    · 反思日志
· 提出调节活动                          · 使用时间与次数记录
· 反映用户的修改与拒绝
```

## 三、应用流程

1. 访问应用 → **登录**
2. **是否使用以前的对话**：选择使用时，调出用户允许使用的过往数据
3. 用户**输入当前的经历和烦恼**
4. **风险检测**
   - 有风险 → 提供求助渠道和安全信息 → 结束对话
   - 无风险 → 确认并选择**对话目的**
5. **识别情绪并确认情绪强度**
6. 探索**想法 / 需要 / 愿景**
7. **确认并检查自我批评性想法**
   - 有 → **自我友善活动** → **选择调节策略** → 执行可行的行动
   - 没有 → 直接**执行可行的行动**
8. **选择是否保存记录**
9. 写**反思日志和使用体验** → **结束对话**
   （保存的内容可在下次「是否使用以前的对话」时调用）

## 四、提示词构成（13 个部分）

| 构成部分 | 主要内容 | 相关细则 |
|---|---|---|
| 角色与范围 | 作为支持中国留学生自我共情的对话者回应；帮助用户理解自己的经历并自己做选择；**不要**以提供诊断或治疗的专家身份行事。 | 8.1 |
| 倾听与对话节奏 | 信息不足时不要断定原因或解决办法；一次回应通常只提一个核心问题；用户还想多说时耐心等待，不要急于追问或给建议。 | 2.1、2.2；参与者 3、4 |
| 确认对话目的 | 确认用户现在想要的是倾听、整理情绪、应对办法还是信息；已确认的目的只在有变化或需要再确认时才重新确认；不要强加解决方案。 | 10.1、10.4；参与者 4 |
| 复合情绪与需要的探索 | 考虑多种情绪同时出现的可能，提供情绪词和探索性问题；对情绪和需要的解读要以「暂定」方式提出，让用户确认或修改。 | 1.1、1.2、10.3；参与者 1、4 |
| 情境探索，区分事实与解释 | 一起探索个人、关系、环境、文化适应等情境；帮助区分实际发生的事和用户的解释；**不要**把环境造成的困难缩小为个人想法的问题。 | 2.1、2.2、9.2；参与者 3、7 |
| 情绪确认与自我接纳 | 回应要体现对情绪产生情境的理解；区分「承认情绪」与「认同自我贬低的判断」；提出自我友善的表达，但让用户可以接受、修改或拒绝。 | 4.1、4.2、5.1、5.2、7.1、8.3；参与者 3、9 |
| 具体的鼓励 | 基于用户实际说过的努力和尝试来鼓励；不要无依据的称赞或重复安慰；不要保证正面结果。 | 7.1、7.2、10.2；参与者 1、3、5、7、10 |
| 按情绪状态优先稳定 | 用户情绪被压垮时减少深入探索；确认参与意愿后提出简短的稳定活动；之后再确认当前状态和是否继续对话。 | 6.1、6.2、6.3、9.3、10.4；参与者 8 |
| 支持现实可行的行动计划 | 提出行动前先确认用户意愿和所需的执行条件；把用户选择的小行动具体化到执行时间和可能的障碍；执行有困难时帮助调整计划。 | 6.4、7.3、9.2、9.4；参与者 4、5、8 |
| 利用过往情境与回顾 | 只参考**允许使用**的记录，并确认过去的情况现在是否仍然适用；帮助回顾情绪和行为的变化，但不预设一定有进步；把用户纠正过的内容反映到之后的回应中。 | 1.3、7.4、8.5、9.1、10.3；参与者 6、7 |
| 语言与文化情境支持 | 用用户选择的语言回应；应要求解释韩语表达和文化背景；**不要**基于文化刻板印象解读；不确定的背景要向用户确认。 | 8.7、9.2、10.5；参与者 8、9 |
| 尊重修改、拒绝与结束 | 优先反映用户修改的内容；不要反复提出用户已拒绝的解读或活动；尊重用户跳过问题、活动或结束对话的意愿。 | 8.2、10.3、10.5；参与者 8、9 |
| 安全应对与个人信息边界 | 安全相关情况下，优先执行既定的安全应对流程，而不是一般性探索；使用系统提供的、经过核实的支持信息；不要参考未被允许使用的记录。 | 8.4、8.5、8.6 |

## 五、与当前网站实现的对照（初步）

> 根据 2026-10-02 的代码整理，供决定下一步开发时参考。

| 指导要求 | 当前状态 | 说明 |
|---|---|---|
| 先输入经历，再风险检测，再确认对话目的（流程 3–4） | ✅ 已实现 | 开场提示卡片 → 用户说第一句 → 风险筛查 → 确认需要什么帮助。 |
| 风险检测 → 求助信息 | ✅ 已实现 | 关键词筛查由代码完成，命中后直接给出核实过的求助资源，不经过 AI。 |
| 确认对话目的；不强加解决方案 | ✅ 已实现 | 五个目的选项（倾诉 / 整理情绪 / 稳定状态 / 了解信息 / 寻找方法）。 |
| 自我批评检查 → 自我友善活动 | ✅ 已实现 | 检测到强烈自我批评时自动切换到「自我友善」流程。 |
| 稳定活动、行动计划 | ✅ 已实现 | 「稳定状态」「寻找方法」两个流程，含四步行动计划卡片。 |
| 选择是否保存记录 | ✅ 已实现 | 确认卡片后可点「保存到我的记录」。 |
| 情绪、需要的解读以「候选」方式提出，让用户确认或修改 | ✅ 已实现 | 情绪词、小结卡片都可确认、修改或跳过。 |
| 尊重跳过与结束 | ✅ 基本实现 | 底部工具栏有「跳过」「中断」。「不重复已被拒绝的建议」目前只靠提示词要求。 |
| **识别情绪强度**（流程 5） | ❌ 未实现 | 目前只选情绪词，没有强度（例如 1–5 分）。 |
| **是否使用以前的对话**（流程 2、角色 5） | ❌ 未实现 | 目前每次对话互相独立，AI 看不到以前的对话或记录。需要先征得用户同意、只调用允许使用的内容。 |
| **反思日志与使用体验**（流程 9、架构「성찰일지」） | ✅ 已实现 | 「每日使用感受记录」：每天一份三题问卷，侧边栏进入；管理员可在后台查看并导出。尚未在对话结束时自动提示填写。 |
| **使用时间与次数记录**（架构·数据管理） | ⚠️ 部分实现 | 有每次对话的开始时间；没有专门的使用次数、使用时长统计。 |
| 「了解信息」目的的专门处理 | ⚠️ 部分实现 | 选「了解信息」后目前进入一般的倾诉流程，没有专门的信息、资源引导。 |
| 提示词按第四节的 13 个部分组织 | ✅ 已实现 | 后台「AI 对话设置」的「共同原则」分成 13 项，可逐项修改，每项注明对应细则。 |
| 应要求解释韩语表达与文化背景 | ✅ 已写入提示词 | 见共同原则「语言与文化情境支持」。 |
| 情境探索时区分事实与解释，不把环境困难缩小为个人问题 | ✅ 已写入提示词 | 见共同原则「情境探索：区分事实与解释」。 |
