# 产品需求文档（PRD）
## 面向中国留学生的AI文化适应自我共情支持应用

---

## 1. 项目背景与研究定位

本项目是一款面向**在韩国学习和生活的中国留学生**的、基于大语言模型API的**双语（中/韩）自我共情支持应用**，用于博士论文研究。

**核心目的**：帮助用户在学业压力、语言障碍、人际关系、研究室生活、家庭期待、经济负担以及偏见或歧视等**文化适应情境**中：
- 识别和表达自己的情绪
- 理解情绪背后的需要与想法
- 减少过度自我批评，以更接纳、友善的方式对待自己
- 在状态允许时选择适合的应对行动

**产品定位**：情绪支持与自我反思的辅助工具。**不提供心理诊断或治疗，也不替代专业咨询**——此边界必须在系统提示词、首次使用引导、帮助页面中反复、清晰地传达（对应细则8.1）。

**研究性质**：本应用是论文研究工具，非商业化长期运营产品。这一性质直接决定了第7章"一次性使用机制"的设计——应用服务于一次性的实验/研究会话，而非日常复用的消费级App。

---

## 2. 产品目标

### 2.1 用户目标
帮助用户降低文化适应过程中的心理压力，提升自我共情能力（识别情绪→理解需要与信念→自我接纳→必要时行动）。

### 2.2 研究目标
产出一条**可运行、可测试的核心对话流程**，作为论文中效果验证、专家评审与可用性评价的对象；保留每个功能点与设计原理/细则的对应记录。

### 2.3 非目标（明确排除）
- 不做心理诊断、临床评估或治疗
- 不做多次使用的长期陪伴型产品（见第7章）
- 不由AI编造机构联系方式或医疗建议
- 不要求用户按固定顺序完成全部13项功能

## 3. 目标用户与使用场景

**目标用户**：在韩国生活/学习的中国留学生，中文为主要母语，部分具备韩语能力，正经历不同程度的文化适应压力。

**典型场景**（对应细则9.2的文化适应问题分类）：
学业压力、语言障碍、人际关系困难、研究室生活、家庭期待、经济负担、偏见或歧视经历、学校生活、行政程序、职业不安等。

**用户进入意图**（系统应先判断，见细则10.1/10.4）：
倾诉、整理情绪、稳定状态、寻求信息、寻找方法——五类意图对应不同的对话策略优先级。

## 4. 核心设计原则（对工程团队的约束）

以下原则源自10条设计原理，是所有功能实现必须遵守的硬性约束，优先级高于具体功能描述：

1. **候选而非断言**：AI提出的情绪、情境、原因解释只能作为"候选/待确认"呈现，用户必须能够否认、修改、补充；确认后的信息才能进入后续对话上下文（细则1.1、2.1、10.3）。
2. **不重复提问**：已确认信息在跨功能模块间共享复用，不要求用户重复输入同一经历（"整合为连贯的使用体验"要求）。
3. **不机械安慰、不过度赞美、不文化刻板印象**：语言生成层需要显式规则约束（细则10.2、8.7）。
4. **不将真实歧视经历个人化归因**：偏见/歧视经验不得被系统默认归为用户的"误解"或"想太多"（细则2.2、4.3、5.5）。
5. **状态优先原则**：自我批评强→先接纳支持；难以继续反思→转向简短稳定活动；仅当用户准备好且愿意时→进入行动计划（细则9.3、10.4）。
6. **用户始终拥有对话控制权**：中止、跳过、换一个问题、调整回应长度、语言切换必须在任意节点可用（细则8.2、10.5）。
7. **安全优先于流程完整性**：检测到自伤/伤人/极端抑郁/惊恐/功能严重下降等风险信号时，立即中断常规流程，转入危机应对（细则8.4）。
8. **权限与数据处理由程序落实，不能只依赖提示词**（细则8.5、8.6、11章）——这是技术架构章节的核心约束。
9. **信息来源可核实**：支持资源的机构名称、联系方式必须来自人工核实的数据源，AI不得编造（细则8.4、功能10）。
10. **数据边界透明**：区分"本次会话临时使用的信息"与"长期保存的记录"，用户对二者分别拥有选择权、查看权、删除权、撤回同意权。

## 5. 核心功能模块清单

以下13项功能整合自设计材料，**不作为独立页面/独立任务栏依次呈现**，而是在对话过程中根据用户当前状态和意图被系统按需调用。

| # | 功能模块 | 一句话说明 | 对应细则 |
|---|---|---|---|
| 1 | 情绪·文化适应经验探索与确认 | 情绪词汇候选、情境识别、情境-情绪-行为结构化 | 1.1-1.3, 10.3 |
| 2 | 原因及解释反思 | 区分个人/关系/环境/文化适应因素；区分事实与解释与未确认信息 | 2.1-2.2 |
| 3 | 价值·适应目标设定与调整 | 基于价值/留学意义设定短中期目标；行为-目标比较 | 3.1-3.2 |
| 4 | 自我友善及自我鼓励表达构成 | 自我批评检测→用户确认→重构为自我友善/鼓励表达 | 4.1-4.2, 7.1-7.2 |
| 5 | 共同人性反思 | 将个人困境与普遍人类经验联结，但不淡化真实伤害 | 4.3 |
| 6 | 正念及情绪·想法距离化 | "我是失败者"→"我现在感觉自己失败了"的表达转换；情绪观察活动 | 5.1-5.2 |
| 7 | 情绪调节与即时稳定 | 情境化策略选择、反应延迟（暂停/呼吸）、压倒性情绪时的即时稳定行动 | 6.1-6.3 |
| 8 | 恢复行动选择与应对计划制定 | 休息/求助/咨询资源/小行动等选项；"要做的行动-实施时间-所需帮助-替代方案"计划模板 | 7.3, 6.4 |
| 9 | 每周恢复经验回顾 | 基于用户自愿保存的记录做周回顾摘要，可跳过 | 7.4 |
| 10 | 安全对话与支持资源指引 | 角色边界说明、非评判语言、危机信号识别与转介 | 8.1, 8.3, 8.4, 8.7 |
| 11 | 对话记录控制与个人信息管理 | 中断/跳过/换问题/调整深度；保存与调用权限的用户自主控制 | 8.2, 8.5, 8.6 |
| 12 | 状态·文化情境驱动的个性化对话运营 | 依据（已同意的）情绪历史、反复情境调整策略强度、深度、节奏 | 9.1-9.4, 10.1-10.2, 10.4 |
| 13 | 双语与统一操作界面 | 中韩语切换、统一的确认/修改/跳过/中止/求助/记录管理交互模式 | 10.5 |

> **实现原则**：功能1-9是"用户支持功能"，10-13是"系统共通功能"（安全/个人信息/个性化/语言交互），后者贯穿并支撑前者，不应被理解为独立的理论再分类，仅为工程实现的分层。

## 6. 对话流程设计

### 6.1 总体流程（默认路径）

```
入口/意图判断 → 情绪·情境探索确认(1) → [原因反思(2)] → 自我友善重构(4)
  → [共同人性(5)] / [正念距离化(6)] → 自我鼓励(4) → [目标设定(3)]
  → [恢复行动/应对计划(8)] → 结束/[周回顾(9)]
```
中括号 `[ ]` 表示"按需触发"，不是必经步骤；系统根据用户当前状态和意图动态决定路径，禁止强制线性推进。

### 6.2 意图分流（入口判断）

用户首次表达后，系统需判断当前主要需求属于以下五类之一，并采用不同的优先策略：

| 意图 | 优先动作 |
|---|---|
| 倾诉 | 情感反映、非评判回应，暂不推进结构化步骤 |
| 整理情绪 | 情境-情绪-行为结构化（功能1） |
| 稳定状态 | 直接进入即时安定化（功能7），跳过深入探索 |
| 寻求信息 | 优先提供信息/支持资源指引（功能10），不做情绪深挖 |
| 寻找方法 | 恢复行动/应对计划（功能8），前提是情绪已基本稳定 |

### 6.3 状态优先的流程打断规则

- 检测到强自我批评表达 → 优先转入功能4（自我友善重构），暂缓目标设定/行动计划类推进。
- 检测到用户难以继续反思（回避、情绪压倒、回复变短促）→ 暂停当前功能，转入功能7（即时稳定）。
- 检测到安全风险信号 → 无条件中断当前流程，进入功能10危机应对子流程，优先于一切其他逻辑。
- 仅当用户在功能4/7完成后自愿选择"继续"或"寻找方法"时，才进入功能3/8的目标与行动类内容。

### 6.4 信息复用规则
情境-情绪-行为、原因分类、已确认的价值与目标，一旦在本次会话中被确认，即写入"会话上下文态"，供后续所有功能模块直接引用，不再重复询问（除非用户主动修改/否认）。

## 7. 一次性使用机制设计（新增关键约束）

> 本节回应用户在本轮明确提出的新约束："每个用户仅使用一次"。这与研究设计（论文实验/评估工具）性质一致：应用不是需要长期留存和复访的消费级产品，而是**单次会话研究工具**。

### 7.1 设计含义澄清（需与用户确认的假设）
"仅使用一次"最可能对应研究场景中的**单次实验会话（single-session intervention）**，即：一个用户身份对应一次完整的对话会话，会话结束/达到设定终点后不可重新开始新会话。以下设计基于此假设，如实际含义不同（例如"一次"指"每天一次"或"每个邀请码一次"），需要用户确认后调整。

### 7.2 身份与准入
- 采用**邀请码/研究参与码（access code）**机制，而非注册账号体系，契合研究招募流程，避免可复用账号带来的多次使用。
- 每个access code与唯一用户身份绑定，一次性标记为"已使用"后失效，无法在其他设备/浏览器重新登录发起新会话。
- 首次进入需完成：知情同意（研究/数据使用）→ 角色与边界说明（细则8.1）→ 语言选择 → 正式进入对话。

### 7.3 会话生命周期
- 会话内允许"中断/稍后继续"（细则11章"稍后继续"要求）：同一access code在**同一次未完结会话**内可以暂停并恢复，这不算作"第二次使用"。
- 判定"已使用/完结"的触发条件需要与用户对齐，建议二选一或组合：
  - (a) 用户主动点击"结束本次会话"；
  - (b) 达到系统设定的会话时长/步骤上限；
  - (c) 超过一定时间（如72小时）未恢复，自动判定为已结束。
- 会话完结后，该access code进入只读状态：用户可查看自己保存过的记录/周回顾摘要（如同意保存），但不能再发起新的AI对话。

### 7.4 与"周回顾"功能(9)的冲突与取舍
功能9（每周恢复经验回顾）在字面上假设多次/跨周使用。在"仅一次"约束下有两种取舍，**需要用户决策**：
- 方案A：本版本中禁用/隐藏周回顾功能，作为未来多次使用版本的预留功能（与prompt接口一并预留，见第8章）。
- 方案B：保留但改造为"会话内即时小结"，即在单次较长会话末尾生成一次性的"本次经验回顾"，不依赖跨周期数据。

### 7.5 数据与研究记录
一次性机制不改变第9章的数据分层原则：临时会话信息与用户同意长期保存的信息仍需分别处理；但由于每用户只发生一次会话，"长期保存"实际上等价于"研究数据留存"，其保存、匿名化、删除流程应与IRB/研究伦理要求对齐。

## 8. Prompt与AI能力的可扩展接口设计（新增关键约束）

> 回应用户提出的"prompt相关功能，留出接口"要求：AI对话的核心策略（情绪识别、原因反思、自我友善重构等）应通过**可配置、可替换的prompt/策略层**实现，而非硬编码在应用逻辑中，以便研究迭代（换模型、调整策略、A/B不同提示词版本）时无需改动前端与流程引擎。

### 8.1 分层设计

```
[对话流程引擎/状态机]  ← 决定"当前该用哪个功能模块、以什么优先级触发"
        ↓ 调用
[策略/Prompt层]         ← 每个功能模块对应一组可配置的system prompt + few-shot + 参数
        ↓ 调用
[LLM API 适配层]        ← 屏蔽具体模型差异（OpenAI/其他），统一输入输出接口
```

### 8.2 接口要求
- 每个功能模块（第5章13项）对应**独立的prompt配置单元**：包含system prompt、语言变体（中/韩）、输出格式约束（如"必须先呈现候选供确认，不能下断言"）、安全护栏规则。
- 配置单元以**外部化配置文件/管理界面**形式存在（而非写死在代码中），支持研究者在不修改代码的情况下调整、替换、A/B测试某一模块的提示词。
- 预留**版本化与追踪能力**：每次对话记录应保留其使用的prompt版本号，便于论文中做"设计要求—实现—测试"的对应分析和效果比较。
- 预留**模型可替换接口**：AI调用层与具体模型/供应商解耦，未来更换模型或对比多模型效果时，流程引擎和策略层无需重写。
- 安全护栏（功能10相关规则，如不评判、不编造联系方式、危机识别）应作为**跨模块的共享中间层规则**，而不是分别写入每个模块的prompt，避免遗漏和不一致。

### 8.3 本版本范围
MVP阶段仅需实现该分层"接口/骨架"（配置结构+版本记录+模型适配层），不要求做出完整的可视化提示词管理后台；后续迭代可在此基础上扩展管理界面。

## 9. 数据与隐私（技术落地要求）

延续原始需求中"权限和数据处理必须由程序落实，不能只依赖提示词"的要求：

1. **信息分层**：区分（a）本次会话临时上下文（仅用于当前对话推理，会话结束/未同意保存即清除）与（b）用户明确同意保存的长期记录。二者在存储层物理隔离。
2. **用户控制面板**：查看已保存记录、删除、撤回同意、查看数据用途说明，均为程序化功能而非仅文案承诺。
3. **最小化收集**：仅收集功能所需与研究所需的最小信息集合，明确告知收集目的、保存期限、使用范围、加密方式、是否有第三方（含LLM API供应商）接触数据。
4. **第三方/外部服务披露**：使用LLM API、部署平台等外部服务时，需在知情同意与隐私说明中列出涉及的数据传输范围（哪些内容会发送给API供应商、是否用于模型训练、保存地域等）。
5. **危机信息来源**：支持资源联系方式来自人工维护的核实名单（数据库/配置表），AI回复层只能引用该名单内容，不能自由生成。

## 10. 界面与交互要求

- 简洁、移动端优先（mobile-first）的响应式Web界面。
- 统一的对话操作条：中止、跳过、换一个问题、调整回应长度、语言切换（中/韩）、帮助入口、记录管理入口，须在对话界面中始终可达（对应功能13）。
- AI提出的候选（情绪词、情境、原因归类）以可选卡片形式呈现，明确带有"确认/修改/不选择"操作，视觉上区分"AI候选"与"用户已确认"内容。
- 安全/边界说明可在帮助页随时复查。

---

## 11. 系统架构分层（逻辑架构）

```
1. 用户界面层 UI          —— 对话界面、卡片交互、语言切换、控制条
2. 对话流程与状态管理层    —— 意图判断、功能模块路由、状态优先打断规则（第6章）
3. AI调用层（Prompt/策略层 + 模型适配层） —— 第8章
4. 回应处理层             —— 候选生成→用户确认→上下文写入；安全护栏统一拦截
5. 数据存储层             —— 临时会话态 / 长期记录（用户同意）/ 研究留存数据 三者隔离
6. 准入与会话生命周期层    —— access code、一次性使用判定（第7章）
```
各层之间通过明确接口通信，UI层不直接访问存储层，AI调用层不直接访问用户身份/权限信息（由回应处理层做中转与校验），以保证"权限与数据处理由程序落实"的要求可验证、可测试。

## 12. 分阶段开发计划

### 阶段0：核心可运行对话流程（MVP，优先级最高）
- 单一默认路径：意图判断 → 功能1（情绪·情境探索确认） → 功能4（自我友善重构） → 功能7（即时稳定，按需触发） → 结束。
- 中/韩双语基础支持、基本控制条（中止/跳过/语言切换）。
- 功能10安全护栏（角色边界说明+基础危机信号检测+人工核实的资源名单）必须在阶段0一并落地，不可后置。
- 第7章一次性使用机制（access code+会话完结判定）。
- 第8章prompt分层骨架（即使只有2-3个模块，也要走"外部配置+版本记录"的结构，不写死在代码里）。
- 数据分层存储（临时态/长期态隔离）。

### 阶段1：扩展反思与目标类功能
功能2（原因反思）、功能3（价值目标设定）、功能5（共同人性）、功能6（正念距离化）接入流程路由。

### 阶段2：行动与个性化
功能8（应对计划）、功能12（状态·情境个性化运营）、功能9（周回顾，取决于第7.4节决策）。

### 阶段3：完善与研究支撑
功能11完整的记录/隐私管理面板、prompt管理界面完善、版本对应记录导出（供论文分析使用）、专家评审与可用性测试所需的埋点/日志。

## 13. 验收与追溯要求

- 每个已实现功能需在交付清单中标注其对应的设计原理编号与细则编号（沿用第5章表格结构），供专家评审核对"设计要求—实现"对应关系。
- 每次prompt/策略调整需记录版本号与调整原因，供"实现—测试"结果回溯分析（服务于论文的迭代评估章节）。
- 安全护栏（功能10）需有独立测试用例集合（如自伤关键词、歧视经历误判等边界场景），作为发布前必过项。

## 14. 待用户确认的开放问题

1. **"每个用户仅使用一次"的确切含义**：是否等同于"单次会话研究工具"（第7.1节假设）？会话完结的判定条件采用7.3节中哪个方案（或组合）？
2. **周回顾功能(9)的取舍**：在一次性约束下采用方案A（预留）还是方案B（会话内小结）？
3. **LLM服务供应商**：是否已确定使用的模型/API（如OpenAI），涉及的数据出境与合规披露需据此细化。
4. **研究伦理审查（IRB）现状**：知情同意文本、数据保存期限、匿名化要求是否已有既定研究伦理批件内容需要对齐进本PRD第9章。
5. **部署环境**：是否已有目标部署平台（影响第11章存储层选型与合规披露）。
