# 功能说明（function.md）

> 中国留学生自我共情对话 AI —— 全部功能一览。更新于 2026-10-04。
> 用户网站：https://emotion.knettf.com　后端接口：https://emotion-api.knettf.com

---

## 一、整体结构

| 部分 | 内容 |
|---|---|
| 用户端 | 登录后与 AI 对话；保存记录、填写每日使用感受、查看历史对话 |
| 管理后台 | 查看对话和用户、管理账号、设置 AI（模型、流程、提示词）、检查与测试、使用说明 |
| AI 对话机制 | 程序决定"现在在哪一步"，管理员的提示词决定"每一步怎么说、怎么问" |
| 安全 | 危机识别与求助信息由程序固定处理，不受提示词影响 |

技术：前端 Vue（部署在 Cloudflare Workers），后端 FastAPI + SQLite（Docker 部署在服务器，通过 Cloudflare Tunnel 对外），模型使用 OpenAI。

---

## 二、用户端功能

### 1. 账号
- 用账号 ID + 密码注册、登录，没有邮箱。
- 忘记密码时由管理员重设。
- 被管理员停用的账号无法登录。

### 2. 对话
- 首次进入会显示说明和同意页，选择对话语言（中文 / 韩文）后开始。
- 界面参考 ChatGPT：AI 回复以全宽正文显示，用户消息为灰色气泡，输入框可自动增高。
  - 电脑上按回车发送，按 Shift+回车换行；手机上按回车换行，点发送按钮发送。
  - 中文、韩文输入法正在选字时按回车，不会误发消息。
- 底部有三个按钮：
  - **换一个问题**：在同一目的下，AI 只换一个新问题。
  - **跳过**：跳过当前这一步。
  - **终止对话**：确认后，AI 写最后一条回复，之后对话锁定，只能查看。
- 对话中会出现的卡片：
  - **小结卡片**（发生了什么—感受—应对）：用户可以点卡片上的按钮确认或修改，也可以直接打字确认。
  - **目的按钮**：5 个常见目的，也可以自己写。
  - **小计划卡片**（先做什么、什么时候、需要谁帮忙、做不到时怎么办）。
  - **求助信息卡片**：只在识别到危机时出现，内容是核实过的求助资源。
- 小结和小计划确认后，可以"保存到我的记录"。
- 可以把当前对话导出成 Markdown 文件。

### 3. 侧边栏 / 菜单
- 开始新对话、最近对话。
- **历史对话**：查看过去的对话，可以删除单段或全部。
- **我的记录**：查看、删除保存过的小结和计划。
- **每日使用感受记录**（每日省察）：每天填写一次问卷。
- 帮助与联系、用户隐私协议、界面语言（中文 / 한국어 / EN）。

### 4. 隐私与数据
- 同意项分 4 类，由用户自己决定：对话记录、情绪记录、文化适应信息、个性化使用。
- 对话只在用户发出第一句话后才创建。超过 10 分钟仍是空对话的，会在服务重启时自动清理。

## 三、AI 对话机制

### 1. 对话流程（默认顺序，来自负责人的 STEP 1–5 和流程图）

| 步骤 | 什么时候进入下一步 |
|---|---|
| 听用户讲述困扰 | 用户确认小结（点卡片或打字确认都可以）；最多 10 轮 |
| 确认对话目的 | 用户选了目的或自己写了之后。选"先平静"跳到情绪调节，选"想想怎么办"跳到小恢复行动 |
| 自我认识探索 | AI 判断这一步完成，且至少 3 轮；最多 12 轮 |
| 确认自我批评 | 用户回答确认问题后，按回答分支 |
| 自我接纳与自我友善 | 自我批评较强时完整进行（2–8 轮）；较弱或没有时只简短进行（1–2 轮） |
| 情绪调节 | AI 判断完成；最多 8 轮。所有人都会经过这一步 |
| 小恢复行动 | 用户确认小计划，或 AI 判断完成 |
| 结束对话 | 总是放在最后 |

- 用户说"告诉我怎么办"时，直接跳到小恢复行动；说"今天先到这里"时，直接进入结束对话。
- 程序识别到用户情绪很激动时，这一轮临时改用"帮用户平静下来"的说明，不改变当前步骤。
- 识别到危机信号（自伤、伤人等）时，不调用 AI，直接回复固定的安全文字，并附上求助信息。

### 2. AI 每一轮收到的内容（按顺序）

1. **程序附加说明**：卡片规则、进度信号、回复语言
2. **管理员说明的开头**（说明下面的内容优先）
3. **共同原则**（已启用的）
4. **当前这一步的说明**，以及加在这一步下的内容（只发当前这一步）
5. **其他**（管理员自己添加的、所有步骤都用的内容）
6. **输出格式（JSON）**
7. **当前进度**提示：小结或计划是否已给过、用户选的目的、自我批评分支
8. 最近的聊天记录（条数可设置，默认 12 条）

以上第 1–7 项的每一个字都可以在后台修改。

## 四、管理后台

后台有 5 个标签页（窄屏下是一行，可以横向滑动）。

### 1. 对话数据
- 按用户、语言、日期筛选对话；查看每段对话的消息和保存的记录。
- 删除对话；导出数据（只包含用户同意保留的内容）。

### 2. 用户管理
- 新建账号、停用 / 恢复账号、删除账号、重设密码、修改角色（用户 / 管理员）。
- 普通管理员只能看到和管理普通用户；超级管理员能看到全部账号。
- 超级管理员账号（如 weekend2000119@gmail.com）排在最前面，以受保护的卡片显示：**没有删除、停用、改角色按钮**，接口也会拒绝这些操作。超级管理员可以在自己的卡片上**重设自己的密码**，但不能重设其他超级管理员的密码。超级管理员身份只能直接在数据库里修改。

### 3. 每日使用感受记录
- 查看用户填写的每日省察。

### 4. AI 对话设置

分成 4 个小标签：模型 / 对话流程 / 提示词 / 检查与测试，一次只显示一块。

**手机上（屏幕宽度小于 768px）只能查看**：所有需要打字的地方（提示词、轮数、目的按钮文字、新增步骤、改名、测试脚本）都改成纯文字显示；停用 / 启用、上下移动步骤、检查冲突、运行测试对话、试聊照常可用。平板和电脑可以正常编辑。

**模型选择**：选择 OpenAI 模型和思考强度。

**对话流程顺序**：
- 拖动卡片调整步骤顺序，可以停用某一步。
- 设置每一步的最少 / 最多轮数。
- 修改目的按钮：文字，以及选中后跳到哪一步。
- 设置 AI 能看到的最近消息条数。
- 顺序不合理时会显示提醒（比如"小恢复行动"排在"自我认识探索"前面）。

**提示词编辑**，分 4 组：

| 分组 | 内容 | 默认状态 |
|---|---|---|
| 共同原则 | 〔负责人原文〕最重要的对话规则、用户可随时使用的指令；〔AI 根据指导意见2整理〕13 段补充原则 | 负责人原文、"角色与范围"、"安全应对与个人信息边界"启用；其余 11 段**默认停用**（和负责人规则有重叠或冲突） |
| 对话步骤 | 8 个步骤，加上"帮用户平静下来时""用户点「结束对话」时" | 中文版已换成负责人原文，并**分成三格**：这一步要达成什么 / 示例问题（一行一个）/ 这一步不要做什么 |
| 其他 | 管理员自己添加的内容，所有步骤都会用到 | — |
| 程序附加说明 | 18 段：输出格式、卡片规则、进度信号、进度提示等 | **默认收起**。带 ⚠️ 的英文字段名是程序读取用的，不能改名或删掉 |

每一段的通用功能：
- 改名、停用 / 重新启用。
- 中文版、韩文版分开编辑（编辑框上方切换）。
- "保存并启用"后，下一句话就生效。
- "修改记录"：查看每一次保存，可以恢复到任意一版。"恢复原始内容"可以回到默认内容。
- 每段都有说明，写明作用、发送时机和来源（负责人原文 / AI 整理 / AI 编写）。
- 对话步骤下可以添加只在这一步生效的内容，也可以添加新的步骤。
- "试聊一下"：用还没保存的修改，在指定步骤试聊几句，不保存。

**检查与测试**：
- **检查冲突**：AI 读一遍某个语言下所有正在使用的内容，用白话列出互相矛盾的地方，并给出修改建议。只提示，不会自动修改。
- **测试对话**：预存几段用户发言脚本（默认 3 段：发表没讲好、和室友有矛盾、只想说说），可以新增、编辑、删除。
  - 点"运行"后，按真实流程把整段对话跑一遍，每句回复都标出当时在哪一步、出了什么卡片。
  - 结果和上一次运行左右对照，便于比较修改前后的差别。
  - 测试在数据库里运行完即撤销，不留下任何数据，也不影响真实用户。

### 5. 使用说明
面向管理员的说明页（中文 / 韩文），包括：
- AI 每轮收到什么
- 每段旁边的来源标记是什么意思
- 怎么写 AI 才更听话
- 改完之后怎么确认效果
- 容易踩的坑
- 各页面的用法

## 五、分工：哪些由管理员决定，哪些由程序固定

| 管理员可以改 | 程序固定 |
|---|---|
| 全部提示词文字（包括程序附加说明） | 现在在哪一步、什么时候进入下一步（判断的机制） |
| 步骤顺序、停用步骤、每步轮数 | 危机识别，以及危机时的固定回复和求助信息 |
| 目的按钮的文字和跳转 | 用户同意与数据保留规则 |
| AI 能看到的消息条数、模型、思考强度 | 卡片字段的读取方式（因此带 ⚠️ 的字段名不能改） |

---

## 六、使用提醒

- 改完提示词后，用"测试对话"跑一遍，或者在前台**开始新对话**测试。在旧对话里测，看不出改动的效果。
- 中文和韩文要分别修改。
- AI 不是程序，做不到 100% 照做。示例问题写得越具体、越多，效果越稳定。
- 改完后用"检查冲突"确认没有前后矛盾的要求。
